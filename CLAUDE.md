# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`@artcosoft/ami-types` is a types-only TypeScript package for the Asterisk Manager Interface (AMI). It covers every AMI action (request, response and the events it replies with) and every AMI event of Asterisk 22. The only runtime code is the `amiAction()` helper and two string enums (`ChannelState`, `QueueMemberDeviceStatus`).

## Commands

- `npm run build`: runs `tsc`, compiling `src/` into `lib/` (CommonJS + `.d.ts`). `lib/` is gitignored.
- `npm run typecheck`: type-checks without emitting. There are no tests (`npm test` is a stub that fails), so this check is how you verify a change.
- `npm run generate`: regenerates all action and event types from `scripts/asterisk/`, then runs prettier over `src/definitions`. It is deterministic, so running it again without input changes produces no diff.
- `npm run extract-docs -- <tag> [asterisk-checkout]`: rebuilds `scripts/asterisk/data/docs-ami.json` from the Asterisk XML docs for a release tag, for example `22.11.0`. It needs git, xmllint and python3, and clones Asterisk into a temp dir unless you pass a checkout. Asterisk itself is not compiled.
- `npm run build_and_publish`: runs clean, build, then `npm publish` to GitHub Packages. `.npmignore` leaves `src/`, `scripts/` and this file out, so only `lib/` ships. Each release bumps `version` in `package.json` in its own commit (`upd: version ...`).

Formatting comes from `.prettierrc.json` (4 spaces, single quotes). Generated files are formatted by `npm run generate`. `package.json` is not formatted with prettier.

## Generated vs hand-written

**Generated:** `src/definitions/actions/**`, `src/definitions/events/**`, `all.actions.ts` and `all.events.ts`. Every one of these files starts with a "Generated by …" banner. Never edit them by hand: `generate.py` deletes and rewrites both directories.

**Hand-written:**
- `src/index.ts` (the public API);
- `generic.types.ts` (`AmiActionPrototype`, `GenericAmiEvent`, `AmiResponse`);
- the shared value types in `channel.types.ts` and `event.types.ts`.

The generator scans these two `.types.ts` files. When a documented enum has exactly the same values as an `export type X = 'a' | 'b'` alias in them, the field uses `X`. Enums such as `ChannelState` are assigned through overrides.

The pipeline lives in `scripts/asterisk/` and uses only the Python standard library:

1. `extract-docs.sh` → `parse_docs.py` → `data/docs-ami.json`. This is the AMI part of Asterisk's XML docs, the same content as docs.asterisk.org. `xi:include` is resolved by xmllint. `<channel_snapshot/>` and `<bridge_snapshot/>` are expanded in Python, the same way `doc/appdocsxml.xslt` does it.
2. `data/source-events.json` covers events Asterisk emits but does not document (`QueueStatusComplete`, `QueueMember`, `DBGetResponse`, `BridgeListItem`, CC*, …). Their fields were read from the C source and every entry cites `file:line`.
3. `data/source-actions.json` records, for each action, its extra `Response` headers, list-item events and complete event. These were read from the C handler, because the XML docs only describe this for a few actions.
4. `overrides.json` holds:
   - corrections where the docs disagree with the source (for example `QueueParams`), each with a `reason` that ends up in JSDoc;
   - backward-compatible request types (`Penalty: string | number`, `Variable: string | string[]`);
   - forced optional/required flags;
   - the folder layout;
   - the `AmiChannelEvent`/`AmiDeviceEvent`/`AmiQueueEvent` groups;
   - which reply events get a required `ActionID`.

### Typing rules the generator applies

- **Request fields:** required only when the docs mark them `required="true"`. A documented enumlist becomes `'a' | 'b' | (string & {})`, which gives autocompletion but still accepts any string. Numbered headers (`Action-000000`, `UnitType(0)`) become template-literal index keys.
- **Event fields:** required by default. A field is optional when the docs say `required="false"`, when its description reads as conditional ("only present if…"), or when it is missing from some instances of a multiply-documented event. Enumlists are strict unions.
- **Event unions:** an action's `Event` slot is the union of its list-item events plus its `*Complete` event. On these reply events `ActionID` is required, except on the ones Asterisk also broadcasts unsolicited.

## Changing types

- **Fix or extend a type:** edit `overrides.json`, or the `data/source-*.json` file for source-derived items. Then run `npm run generate && npm run typecheck`.
- **Move to a new Asterisk version:**
  1. Run `npm run extract-docs -- <tag>`.
  2. Run `npm run generate`. It stops with an error when an action has no entry in `data/source-actions.json` or refers to an unknown event.
  3. Add the missing entries from the new source.
  4. Review the diff of `data/docs-ami.json`.
